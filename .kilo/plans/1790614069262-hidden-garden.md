# OTC Proof Trading Desk — DMZ Design & Implementation Plan

**Status:** planned, not started. **Location:** new packages inside `lean-worker`.
**Settlement decision:** off-chain, priced in metameme. No chain, no mint, no wallet keys.

---

## 1. Objective

A secure DMZ inside `lean-worker` where agents trade **parts of Aristotle proofs** bilateral,
off-book, under kernel-checked rules:

- a **system user** (`otc-desk`) and a **hardened systemd service**
- a **web GUI** built on the Cloudflare Workers relay pattern
- a **relay listener** that gossips about proofs with other agents
- **layered release** (self / open-source) gated by human approval in the GUI
- a **minimal knowledge base** bootstrapped from wiki, OSM, LMFDB, OEIS, Wikidata

The commodity is not a claim. It is an artifact the desk can **re-check itself** — the rule
already proved in `Bounty.accepts_recheckedLocally`.

## 3. Design

### 3.1 Layered release — lane layers, each with a proved bit bound

Per user decision: **both**. The layers are lane-shaped and practical; each one is then
instantiated against the already-proved `RevealLeakage` arithmetic.

| Layer | Contents | Audience | Reveal kind | Cumulative `k` |
|---|---|---|---|---:|
| **L0** public | Statement, target node, lane, price, escrow mode | anyone | coordinate | 0 |
| **L1** peer | Proof sketch, worked cases, hash-pinned census CSVs | counterparty | coordinate | ≤ `k1` |
| **L2** escrow | Full Lean source, CI digest, build receipt | counterparty, in escrow | coordinate | ≤ `k2` |
| **L3** self | Identity, keys, stake, private KB slice | operator only | never | — |

Mechanism. `layerCoords : Layer → Artifact → Finset (Fin n)` names the coordinates each
layer reveals. The bound is then not asserted but instantiated:

```lean
-- per layer
theorem layer_leak (L : Layer) : card_consistent s (layerCoords L s) = 2 ^ (n - |layerCoords L s|)
-- cumulative
theorem schedule_residual : |⋃ layerCoords L₀…L_i| ≤ k  ⟹  residual ≥ n - k
```

**The caveat is load-bearing.** `RevealLeakage.one_bit_reveal_can_leak_everything` shows a
single revealed bit that is *not* a coordinate ("is the secret zero?") can on one outcome
leave one consistent secret — a worst-case leak of `n` bits from one revealed bit. So the
desk claims the bound **only for coordinate reveals**, and a layer that wants to reveal a
predicate must instead pay in coordinates. This is recorded as a hypothesis on every
`Release` value, not buried in a README.

Mapping onto `TypedDMZ`: releasing layer `Li` is a `Capability` grant on the trade's fields;
`committee_veto_absolute` still holds, so no layer release can override a failed kernel check.

### 3.2 Settlement — four rails, per user decision "all of the above and more"

| Rail | Mechanism | Settles today? |
|---|---|---|
| **A — units** | Board units 1:1 (`BountyBoard`) | Yes, the default |
| **B — metameme** | `PaymentMorphism` on the artifact. Off-chain, priced | Price only |
| **C — credits** | `Kant.Credits` — earn by serving, spend on acceptance checks | Yes, for checkers |
| **D — out-of-band** | Opaque `settlementRef`; the DMZ never sees an account | Reference only |

Rail B in full: amount = `PaymentMorphism` applied to a measured property of the artifact —
Lean line count, check CPU-minutes, or `LmfdbComplexity(level, weight)` for the cross-check
lane. A coin is minted per delivery and `PaymentTransaction::verify` gates the release,
exactly as the Rust does.

The rule that keeps this honest is restated from `HintRelation.lean`:

```lean
-- price is a function of the artifact ALONE
def price (a : Artifact) : MetamemeAmount := ...
theorem price_independent_of_claim : price a = price a'  -- a seller cannot
                                     -- inflate its own baseline
```

`baselineCost` is a function of the instance only; `checkCost` is charged inside the
inequality, so a "proof" that costs more to check than it saves is rejected. That is what
stops a desk from being used as a laundering route for junk.

### 3.3 Escrow — all three modes, selectable per trade

| Mode | Mechanism | Inherited guarantee |
|---|---|---|
| **hash-chained** | `Proxy/Core.lean` `Receipt` chain; release needs seller + buyer tags | Complete mediation; tamper-evident; denial is inert |
| **quorum m-of-n** | `Protocol/Soundness.lean` `agreed`/`disagreed`/`unknown` | Release only on `agreed` |
| **trust + dispute** | Human review | The floor, always available |

A trade names its mode in the ticket. The desk refuses any mode it cannot prove solvent under
`totalPayout_le_totalEscrow`.

`PrerequisiteCap.lean` applies at the desk level: no single seller may hold more than
`num/den` of any prerequisite type, so no one party can block every quest needing it
(`quest_survives_single_withdrawal`). The same module proves this does **not** give Sybil
resistance — the desk says so on the page rather than implying otherwise.

### 3.5 Knowledge base — p2p fetch with zkTLS-style witnessing

Minimal KB, centred on the core bootstrap: **wiki, OSM, LMFDB, OEIS, Wikidata**, plus the
project's own `data/*.json` (bounties, work units, claim graph, eta catalogue, census).

Per user decision: a **p2p network of fetching and witnessing**, not a one-shot mirror.

- Peers fetch over the relay; each record carries a **witness**: query, date, response
  digest, fetcher peer id.
- A record is admissible only if witnessed. This is bounty **B12.17**'s own rule — "reporting
  matches and mismatches with the query used and the date" — promoted to a general KB rule.
- Verification is cheap and cryptographic: `MonsterWalkZKP.lean` shows a DASL address verifies
  in 3 modular reductions mod 71, 59, 47. Witness integrity uses the same idea.
- Because this is `Lane.metadata`, **a KB hit is never payable as evidence**
  (`metadata_never_accepted`, `metadata_not_wellFormed`). The KB informs; it does not settle.

`OeisSimilarity.lean` is the worked precedent for scoring: Jaccard over integer term sets,
`jaccard_le_one`, `matched_le_total`, and an executable fixture exercising the whole pipeline
end to end. The desk reuses that machinery rather than writing a matcher.

### 3.7 Gossip about proofs

The listener gossips roster announcements, reusing `Kant.Rendezvous.lean` unchanged:

```lean
theorem merge_preserves          — gossip never loses a peer
theorem merge_delivers          — everything heard is recorded
theorem merge_perm              — order is irrelevant
theorem discovery_transitive    — A gossips B, B gossipped C ⟹ A learns C
theorem best_congr              — two clients that heard the same things dial the same address
theorem relay_cannot_forge      — a hostile relay can withhold but not forge
```

The payload is an `Announce` extended with a `proofGossip` field — bounty ids, lane, claimed
milestone, price. No proof content is ever gossiped, only its address.

## 5. Verification

Per step: `lake build` for the stage, `gokujo check` for the gate, and the axiom audit
equivalent of `scripts/axiom_audit.sh` — **no `sorry`, no new axioms**, corpus sweep clean.

End-to-end, before the desk is considered working:

- two clients complete a full trade over the desk relay, and the transcript is **identical**
  from two different routes
- a forged trade ticket is refused (`relay_cannot_forge`, re-checked client-side)
- a layer-2 promotion without approval is refused
- an L3 promotion is refused outright, always
- escrow releases only on two tags; a single tag is inert
- a quorum release fires only on `agreed`; `unknown` and `disagreed` both hold
- a rejected submission costs the submitter their deposit
- a `Lane.metadata` KB hit pays nothing
- the desk runs with the core mounted read-only and cannot write to it

## 6. Risks, stated plainly

- **`P2P.Tag` literally carries its own signing key.** That is the existing project's
  idealisation convention, not a real MAC. It is fine for a model and fine for a board that
  says "no funds exist". It stops being fine the moment the desk holds value worth stealing.
  Fix before first real trade, not after.
- **Metameme is priced, not paid.** No mint, no liquidity, no chain keys. Rail A clears
  today. Do not print a "market price" or "paid in metameme" claim in the GUI.
- **Board prices are not a currency.** `Bounty.lean` says so outright. The desk must not
  contradict its own settlement core.
- **Sybil-open by construction.** `cap_does_not_imply_sybil_resistance` is proved. Say so on
  the page.
- **Gödel.** The system cannot prove its own consistency. This is why `UmweltGodelTrust`
  makes trust architectural — minimal kernel + external audit + architectural separation —
  and why the approval step is a human being rather than a predicate. The board's four
  review-only bounties exist for exactly the same reason: the project cannot supply
  independent review from inside, so those four are the only trades it cannot self-settle.
- **Stale paths.** The installed `kant-relay.service` points at a deleted directory. Verify
  every path at install time; do not copy it.
- **Acceptance checking is expensive.** 48.9 CPU-min per cold corpus check. A popular desk
  that accepts everything is a DoS on itself. `Policy.byteBudget` and `fuelBudget` bound it.

## 7. Explicitly not doing

- No chain deployment, no token mint, no wallet keys in the DMZ — settled, off-chain only.
- No rewriting `Market/Bounty.lean` or `TypedDMZ.lean` — imported and extended, not forked.
- No live LLM calls inside the DMZ at trade time.
- No `Lane.metadata` KB hit is ever payable.
- No claiming a `payout` is a `promotion` (`one_payout_never_promotes`).
- No posting a bounty in the metadata lane (`metadata_not_wellFormed`).
